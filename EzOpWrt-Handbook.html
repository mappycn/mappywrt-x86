01背景与成果

原 EzOpWrt（sirpdboy 基于 lede + 私有插件包）自 2025-02 起停止免费版更新，只做 VIP，无法在线升级。本机没有 Docker、WSL 被安全策略禁止，无法本地编译（需要 Linux + 大小写敏感文件系统 + 40G 空间 + 2~3 小时），所以改为 GitHub Actions 云编译。

项结论
基线源码ImmortalWrt openwrt-24.10（6.6 内核），x86/64 Generic
引导方式Legacy BIOS：CONFIG_GRUB_IMAGES=y + CONFIG_GRUB_EFI_IMAGES=n → 产出 combined.img.gz；UEFI 版是 combined-efi.img.gz，两者不能混
根分区2048MB ext4 可写，占位符 __ROOTFS_SIZE__ 在编译时由 diy-part2.sh 替换
插件体系sirpdboy 各单插件仓库直连 clone 到 package/ezopwrt/（聚合库已被 GitHub 屏蔽，只能逐个拉）
编译耗时约 1.5 ~ 3.5 小时；GitHub 公开仓库 Actions 免费额度内
最终产物build-3 Release 成功，含 .img.gz + .sha256
本机无法本机编译这一约束没变；以后所有固件更新都走「改配置 → push → Actions → 下载」这条路，不要尝试在 Windows 本地编。

3.3 下载与校验

# 产物名
EzOpWrt-x86_64-BIOS-2048M-YYYYMMDD.img.gz
EzOpWrt-x86_64-BIOS-2048M-YYYYMMDD.img.gz.sha256

# Git Bash 里校验
sha256sum -c EzOpWrt-x86_64-BIOS-2048M-YYYYMMDD.img.gz.sha256
gzip -t EzOpWrt-x86_64-BIOS-2048M-YYYYMMDD.img.gz && echo "压缩流完整"
快压/WinRAR 可能提示「有效数据外包含额外数据 / 发生错误 2」：这是 OpenWrt 镜像编译流尾部的 trailing garbage，不是文件损坏。gzip -t 只报这一条、.gz 的 sha256 与 Release 一致、解压出的 .img 与官方压缩流一致即安全。推荐 Etcher 直接选 .img.gz 写盘，不必先解压。

4.1 增删包

编辑 configs/packages.config，把对应 CONFIG_PACKAGE_xxx=y 注释掉或改成 =n；加包就补一行 =y。

4.2 加 PassWall（示例）

4.3 加 AdGuardHome（示例）

# diy-part1.sh 末尾（它在 feeds update 之前执行，追加 feed 安全）

07刷机与首次启动

  1. 写盘方式见 3.4；BIOS 必须是 Legacy / CSM，选 UEFI 会卡在 GRUB。
  2. 网线接 eth0（x86 默认 LAN），浏览器开 http://192.168.8.1，root / password。
  3. 第一件事改密码：系统 → 管理权，或 SSH 里 passwd root。
  4. 界面默认简体中文（lang=zh_cn + 29 个中文包），主题为 KuCat。
  5. 看不到「服务」分类 → 先 Ctrl+F5，仍不行看 第 10 节。
passwd root
uci show luci.main | grep -E 'lang|mediaurlbase'
opkg list-installed | grep luci-i18n | wc -l        # 应为 29 左右
cat /etc/banner                                     # 登录横幅含默认地址提示
关于「扩容」：README 里写的 partexp 扩容是针对「系统盘还有未分配空间」的通用做法。这台实机情况不同：固件刷在 U 盘 /dev/sda（64G，只用了 32M boot + 2G rootfs），而 29G 是机身 eMMC /dev/mmcblk0p1，已自动挂载为数据盘。直接拿这块 eMMC 当数据盘用即可，不需要给 rootfs 扩容，也不要把 eMMC 当成系统盘去扩。

08硬件 / 网卡确认

这台机器 lspci 命令不存在，用下面三条判断网卡（在路由器上执行，不是本机）：

ip -br link                                   # 看有几个网口：eth0 / eth1
ethtool -i eth0                               # 看驱动
dmesg | grep -i -E 'r8168|r8169|igb|e1000|link is up'
实测结果结论
ethtool -i eth0 → driver: r8168Realtek RTL8111/8168 千兆网卡，不是 Intel i210/i211
dmesg 两次 r8168 ... loaded，Link Up 1Gbps/Full2 个千兆口，无 2.5G
x86 Generic 默认LAN = eth0，WAN = eth1，与原固件一致，不用改网口绑定

因此 packages.config 里 kmod-r8168 是有效项；kmod-igb / kmod-e1000e 只是给其它机型兜底，留着无害。r8169 与 r8168 互斥，不要同时启用。

09旁路由切换（只做旁路由）

脚本 extras/bypass-mode.sh，已上传到路由器 /root/bypass-mode.sh。它会：LAN 改静态 IP 并把网关/DNS 指向主路由 → 关本机 DHCP → 关 WAN/WAN6 → LAN 区开 masquerade 与转发 → 关 UPnP → DNS 只允许本网段。

执行后 SSH / LuCI 会立刻断开，用新 IP 重新连。改网络配置前确认主路由 DHCP 已开启，否则可能失联。

9.1 实际用的命令

# Windows cmd 必须用双引号（cmd 不剥离单引号，远程会收到带引号的整行）
ssh -o StrictHostKeyChecking=accept-new root@192.168.36.3 "sh /root/bypass-mode.sh 192.168.36.1 192.168.36.3"

# 或者先 ssh 登录，在路由器 shell 里执行
sh /root/bypass-mode.sh 192.168.36.1 192.168.36.3

参数含义：<主路由IP> <本机IP>。保持现有 IP 不变最不容易失联。

9.2 切换后验证

uci show network.lan | grep -E 'ipaddr|gateway|dns|proto'
uci get dhcp.lan.ignore                 # 应为 1
uci get network.wan.proto               # 应为 none
ip route | grep default                 # default via 192.168.36.1
ping -c 3 192.168.36.1
ping -c 3 www.baidu.com

9.3 让它真正生效（在主路由上做，二选一）

  • 全屋生效：主路由 DHCP 把「默认网关」和「DNS」都改成 192.168.36.3，设备续租后全部走旁路由。
  • 按设备生效：只给需要的设备手动设网关 = DNS = 192.168.36.3。

坑：主路由的 DNS 不能再指回旁路由（DNS 环路）；旁路由的 DHCP 别再打开；科学上网插件要开 DNS 转发/劫持，否则分流不生效。

9.4 SSH 主机密钥变更

# 刷机后 dropbear 重新生成密钥，Windows 会报 REMOTE HOST IDENTIFICATION HAS CHANGED
ssh-keygen -R 192.168.36.3

当时核对过的 ed25519 指纹 SHA256:h3o4V9/Isd/Ojodc+qVhK39IJOVEvEVVICucu8sYiCc 与屏幕提示完全一致，属刷机后正常变更，不是中间人。清理旧记录后重新连接确认即可。

10菜单 / 插件「不显示」排查

「网络唤醒和 HomeProxy 怎么不在里面」「看不到服务菜单」先后出现过，有两个不同原因，按顺序排查：

原因一：LuCI 菜单索引缓存缺项

rm -f /tmp/luci-indexcache.* /tmp/luci-modulecache/*
/etc/init.d/rpcd restart
/etc/init.d/uhttpd restart
# 然后浏览器 Ctrl+F5 强刷

验证插件确实编进去了：opkg list-installed | grep -E 'wol|homeproxy|etherwake'；也可直接访问 /cgi-bin/luci/admin/services/wol 绕过菜单。

原因二（真因）：KuCat 的「常用菜单 basic」隐藏了整个服务分类

KuCat 3.3.2 的 /www/luci-static/resources/menu-kucat.js 默认 currentCategory:'basic'，按硬编码白名单过滤菜单；白名单全是老版路径（services/AdGuardHome、network/netspeedtest 等本机没有），导致 admin/services 整个分类不可见。分类状态存在浏览器 localStorage['luci-menu-category']，所以服务端清缓存没用。

F=/www/luci-static/resources/menu-kucat.js
cp "$F" "$F.bak"
sed -i "s/currentCategory:'basic'/currentCategory:'allmenu'/; s/savedCategory==='basic'||savedCategory==='allmenu'/savedCategory==='allmenu'/" "$F"
node --check "$F" && echo "JS 语法 OK"
/etc/init.d/uhttpd restart
# 浏览器控制台（若仍被旧记忆覆盖）
localStorage.setItem('luci-menu-category','allmenu'); location.reload()
这个修复已固化到工程 files/etc/uci-defaults/98-kucat-menu，重新刷本工程出的固件会自动生效。界面右上角也有「切换到全部菜单」的小图标可手动切。想让顶部快捷栏常驻：uci set kucat.@basic[0].setbar='1' && uci commit kucat。

11HomeProxy 与日志排障

11.1 「升级」其实是更新规则资源

LuCI 里的「更新资源」只更新 CHINA_IP4 / CHINA_IP6 / CHINA_LIST / GFW_LIST 规则，不会升级软件包。实测包仍是 luci-app-homeproxy 26.315.10333~cc142cd、sing-box 1.12.25-r1，opkg list-upgradable 无待升级项，这是正常的。

opkg list-installed | grep -E 'homeproxy|sing-box'
opkg list-upgradable
tail -n 30 /tmp/run/homeproxy/sing-box-c.log
grep -i -E 'CHINA|GFW' /var/log/homeproxy/homeproxy.log 2>/dev/null | tail -10   # 路径以实机为准
sing-box check -c /var/run/homeproxy/sing-box-c.json
curl -x http://127.0.0.1:5330 -m 12 -s -o /dev/null -w 'google=%{http_code}\n' https://www.google.com
curl -x http://127.0.0.1:5330 -m 12 -s -o /dev/null -w 'github=%{http_code}\n' https://github.com

监听端口：5330 mixed、5331 redirect、5332 tproxy、5333 DNS。核查时 google / baidu 均返回 200、sing-box check 通过、2 个 vless 节点且 main_node 有效，结论是资源更新成功。
