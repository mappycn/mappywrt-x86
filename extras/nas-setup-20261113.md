# N4200 旁路由 29G 网盘部署记录（2026-11-13）

设备：EzOpWrt / ImmortalWrt 24.10，旁路由 `192.168.36.3`，主路由 `192.168.36.1`  
目标：把机身 29G 空间做成网盘，且能从外网访问

---

## 一、摸底结论

| 项目      | 实测                                                                                     |
| ------- | -------------------------------------------------------------------------------------- |
| 29G 空间  | 机身 eMMC `/dev/mmcblk0p1`，28.5G，已是 ext4，自动挂 `/mnt/mmcblk0p1`，可用 27.0G —— **无需分区、无需格式化** |
| 系统盘     | USB 闪存 `/dev/sda`（57.6G，只用了 32M boot + 2G rootfs，另有约 55G 未分配，暂未动）                      |
| 内存 / 架构 | 3.8G / x86_64，足够跑网盘                                                                    |
| 软件源     | 直接提供 `filebrowser 2.43.0`、`cloudreve 4.9.2`、`tailscale 1.80.3`、`cloudflared 2025.5.0`  |
| 已装组件    | `lucky 2.27.2`（未启用）、`ddns-go 6.12.0`（未启用）、`samba4`、`docker 27.3.1`                     |
| 公网出口    | `116.226.121.11`（上海电信）；**无全局 IPv6 地址**                                                 |
| 旁路由防火墙  | lan zone `input=ACCEPT`，INPUT 默认 ACCEPT —— 主路由映射进来的流量可以到达本机端口                          |

**选型**：`filebrowser`（Go 单文件，约 12MB 内存，自带上传/下载/预览/分享链接/多用户），不用 Docker、不用 PHP/数据库，最适合这台设备。数据目录 `/mnt/mmcblk0p1/nas`。

## 二、已完成的改动（全部已验证）

```sh
# 1) 开机自动挂载写死（原先靠 anon_mount 碰运气），已备份 /etc/config/fstab.bak-20261113
cp /etc/config/fstab /etc/config/fstab.bak-20261113
uci set fstab.@mount[0].enabled='1' && uci commit fstab
mkdir -p /mnt/mmcblk0p1/nas

# 2) 安装
opkg install filebrowser            # filebrowser 2.43.0-r1

# 3) 改掉两个危险的默认值（原 root_path='/'、enabled='0'），已备份配置
cp /etc/config/filebrowser /etc/config/filebrowser.bak-20261113
uci set filebrowser.config.enabled='1'
uci set filebrowser.config.listen_port='8080'
uci set filebrowser.config.root_path='/mnt/mmcblk0p1/nas'
uci set filebrowser.config.disable_exec='1'      # 禁止在网页里执行命令
uci commit filebrowser
/etc/init.d/filebrowser enable

# 4) 改掉首次启动生成的 admin/admin 弱口令
/etc/init.d/filebrowser stop
filebrowser users update admin -p '<见下方管理员密码>' -d /etc/filebrowser/database.db
filebrowser users update admin --perm.execute=false -d /etc/filebrowser/database.db

# 5) 降权：不再用 root 跑（已备份 /etc/init.d/filebrowser.bak-20261113）
#    在 init 脚本 procd 段插入 user nobody / group nogroup
chown -R nobody:nogroup /etc/filebrowser /mnt/mmcblk0p1/nas
/etc/init.d/filebrowser start
```

## 三、外网访问：你需要在主路由做的一步

用户已确认主路由可以做端口映射。推荐规则：

| 项     | 值                                                        |
| ----- | -------------------------------------------------------- |
| 协议    | TCP                                                      |
| 外部端口  | `28080`（高位非标端口，别用 80/443/8080 —— 家宽常封 80/443，8080 被扫描最多） |
| 内部 IP | `192.168.36.3`                                           |
| 内部端口  | `8080`                                                   |
| 名称    | `nas`                                                    |

映射后，手机**关掉 WiFi 用 4G/5G** 打开：`http://116.226.121.11:28080`

### 先确认一件事（决定映射是否真的有效）

在主路由管理页看 **WAN 口 IP**：

- 如果等于 `116.226.121.11` → 是公网 IPv4，映射直接生效；
- 如果是 `10.x` / `100.64.x` / `172.16~31.x` / `192.168.x` → 运营商 CGNAT，映射**不会生效**，需要换成 Tailscale 或 Cloudflare Tunnel（软件源里都有，我可以配）。

> 旁路由 WAN/WAN6 已按之前的旁路由脚本关掉，所以不必在旁路由上做任何端口放行，只需主路由一条映射。

## 四、现在的安全状态（公网暴露前必读）

已做：

- 根目录限定到数据盘，禁止 Web 端执行命令，服务以 `nobody` 运行；
- 弱口令 admin/admin 已换成 24 位强密码并验证失效；
- 开机自启、断电重启后数据盘与网盘都会自动恢复。

**还没做、且必须说清楚**：目前是 **HTTP 明文**，登录密码和文件内容在公网是明文传输的。短期使用建议：

- 只映射 `28080` 这一个端口，**绝对不要**把 LuCI(80)、SSH(22)、Samba(445)、lucky(16601) 映射出去；
- 用完可以考虑在主路由临时关掉映射；
- 别在公共 WiFi 下上传敏感文件。

要彻底解决，需要**域名**（阿里云/腾讯云/Cloudflare/DNSPod 任意一家均可）：

1. `ddns-go`（管理页 `http://192.168.36.3:9876`）把域名 A 记录指向动态公网 IP；
2. `lucky` 反向代理 `28080 → 127.0.0.1:8080`，用 DNS-01 自动申请 Let's Encrypt 免费证书，对外变成 HTTPS；
3. 可选再加访问白名单 / 二次认证。

告诉我域名和 DNS 服务商，我可以直接把这两步配好。

## 五、备选方案（不映射端口、更安全）

如果只有自己和家人的手机/电脑需要访问，`tailscale`（源里 1.80.3）更省心：不用公网 IP、不用端口映射、不开任何入站端口，设备装客户端后走 `100.x.x.x:8080`，公网扫描器完全看不到。`cloudflared` 则适合需要把链接分享给别人、又不想暴露家庭 IP 的场景（需要 Cloudflare 账号 + 域名）。
