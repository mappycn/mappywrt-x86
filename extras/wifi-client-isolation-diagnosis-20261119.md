## 一、现象

用户电脑（本机 `192.168.36.61`）把默认网关/DNS 改为 `192.168.36.3` 后：
- `ping www.baidu.com` 100% 丢包，浏览器打不开
- 本机 ping 网关 `192.168.36.3` 正常（1~7ms）
- DNS 向 `192.168.36.3` 查询正常（能返回百度 A/AAAA 记录）

## 二、根因（抓包确认，非旁路由配置问题）

**旁路由 → 本机 WiFi 客户端方向丢包，本机 → 旁路由方向正常。**

决定性证据：

1. 旁路由主动 `ping 192.168.36.61` → **100% 丢包（0/2）**
2. 旁路由 ping 其他客户端全部正常：
   - `.1`（主路由）2/2、`.11` 2/2、`.4` 2/2、`.71` 2/2
   - **唯独 `.61` 0/2**
3. tcpdump 抓包：旁路由发出的 ICMP echo request **正确从 eth0 发出**，二层头正确：
   ```
   f4:4d:30:c0:50:d8 > dc:53:60:6b:ac:ec  192.168.36.3 > 192.168.36.61: ICMP echo request
   ```
   但**没有任何 reply 回来**。
4. 旁路由侧无 ebtables 规则、无无线隔离、ARP 正常（`dc:53:60:6b:ac:ec REACHABLE`）、br-lan FDB 里 .61 的 MAC 在 port 1（eth0）。
5. 旁路由自身访问外网完全正常：
   ```
   br-lan Out / eth0 Out  IP 192.168.36.3 > 223.5.5.5: ICMP echo request
   eth0  In  / br-lan In  IP 223.5.5.5 > 192.168.36.3: ICMP echo reply
   ```

结论：**本机 `192.168.36.61` 是 Intel Wireless-AC 7265 无线网卡，通过 WiFi 连接到主路由的 AP**。旁路由（有线，eth0）回包给这个 WiFi 客户端时，帧到达二层网络但客户端收不到——典型的是**主路由 AP 开启了「无线隔离 / AP Isolate / 客户端隔离」**，或 WiFi 客户端与有线侧二层转发被 AP 阻断。

旁路由的 fw4 / HomeProxy / masquerade 全部正常——这从"其他有线客户端都能收到旁路由回包"即可证明。上一轮修复的 44 条透明代理规则没有问题。

## 三、为什么之前"模拟客户端"测试全失败

- 本机临时加 /32 路由：包源 IP 是本机 .61，回包路径经 masquerade 后不对称 → 失败（假象之一）
- netns + veth 模拟：veth 加入 br-lan 后 ARP 被桥隔离 → 失败（假象之二）
- 但本机真实配网关 36.3 也失败：这次是**真问题**，根因就是 WiFi 客户端隔离导致旁路由回包到不了 .61

## 四、解决方案（按推荐顺序）

### 方案 A — 让旁路由回包绕开 WiFi 隔离（推荐，不改本机）
在主路由管理页关闭 **「AP 隔离 / 无线隔离 / Wireless Isolation / 客户端隔离」**。位置通常在「无线设置 → 高级」里。关闭后 WiFi 客户端能与有线旁路由正常二层通信，旁路由方案即可正常工作。

### 方案 B — 本机改用有线接入
把本机接到与主路由/旁路由同一交换机的有线口，问题立即消失（其他有线客户端 .11/.4/.71 都正常）。

### 方案 C — 本机不经过旁路由
保持本机网关 `192.168.36.1`（当前状态），本机访问外网直连主路由；只让需要代理的设备走旁路由。这是当前实际可用的状态。

### 方案 D — 旁路由改用「主路由模式」而非单臂旁路由
需要重新接线（旁路由 WAN 接主路由 LAN，本机接旁路由 LAN），改动较大，不推荐。
